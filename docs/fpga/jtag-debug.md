# JTAG Debug Build Guide

## Overview

The JTAG debug wrapper (`riscv_processor_jtag_debug`) provides full internal visibility through explicit ILA/VIO instantiation, using only 12 I/O pins.

## Build Flow

```bash
# Create project
make create-project-jtag

# Full implementation with bitstream
make implement-jtag
```

### Using Vivado Directly

```bash
# Create project
vivado -mode batch -source scripts/build_vivado.tcl -tclargs jtag

# Synthesize and implement
vivado -mode batch -source scripts/run_synthesis_impl.tcl -tclargs jtag
```

## ILA/VIO Integration

### Generated IP, explicit instantiation

The wrapper instantiates the ILA and VIO cores by name. The matching IP is
generated by `scripts/build_vivado.tcl` (`create_debug_ip`) for the `jtag`
target — ILA: 13 × 32-bit probes, depth 1024; VIO: 3 inputs / 2 outputs, 32-bit.
The wrapper does **not** define black-box modules for them: doing so collides
with the generated IP stubs (Synth 8-9873), and the IP stub has no `C_DATA_DEPTH`
parameter to override (Synth 8-7136). Vivado binds the instantiations to the
generated IP by name.

```systemverilog
ila_riscv_processor u_ila (
    .clk     (clk_int),                  // 50 MHz core clock
    .probe0  (pc_debug),                 // [31:0] Program Counter
    .probe1  (instruction_debug),        // [31:0] Current Instruction
    .probe2  (alu_result_debug),         // [31:0] ALU Result
    .probe3  (reg_debug_data1),          // [31:0] Reg Read Data 1
    .probe4  (reg_debug_data2),          // [31:0] Reg Read Data 2
    .probe5  (mem_debug_data),           // [31:0] Memory Read Data
    .probe6  ({27'd0, reg_debug_addr1}), // [31:0] Reg Read Addr 1
    .probe7  ({27'd0, reg_debug_addr2}), // [31:0] Reg Read Addr 2
    .probe8  (immediate_debug),          // [31:0] Generated Immediate
    .probe9  ({31'd0, reg_write_debug}), // [31:0] Reg Write Enable
    .probe10 ({31'd0, mem_read_debug}),  // [31:0] Mem Read Enable
    .probe11 ({31'd0, mem_write_debug}), // [31:0] Mem Write Enable
    .probe12 ({31'd0, branch_taken_debug}) // [31:0] Branch Taken
);

vio_riscv_processor u_vio (
    .clk           (clk_int),
    .probe_in0     (pc_debug),           // [31:0] PC Status
    .probe_in1     (instruction_debug),  // [31:0] Instruction Status
    // 17 + 7 + 8 = 32 bits (no truncation)
    .probe_in2     ({17'd0, instruction_debug[6:0], branch_taken_debug,
                     mem_write_debug, mem_read_debug, reg_write_debug,
                     jump_op, branch_op, processor_active, error_flag}),
    .probe_out0    (),  // reserved
    .probe_out1    ()   // reserved
);
```

> **Windows path-length note**: inserting the `dbg_hub` debug core during
> implementation requires the Vivado temp path to be ≤146 characters
> (`[Chipscope 16-302]`). This repo's deep `build/...` path exceeds that on
> Windows. Build the JTAG target from a short path: map the repo with
> `subst R: <repo>`, remove the old `build/vivado/riscv_processor_jtag_debug`
> project, then run `vivado -mode batch -source R:/scripts/run_synthesis_impl.tcl
> -tclargs jtag` so the project is recreated under the short `R:` path.

## Debug Capabilities

### ILA Probes (13 x 32-bit)

| Probe | Signal | Description |
|-------|--------|-------------|
| 0 | `pc_debug` | Program Counter |
| 1 | `instruction_debug` | Current Instruction |
| 2 | `alu_result_debug` | ALU Result |
| 3 | `reg_debug_data1` | Register Read Data 1 |
| 4 | `reg_debug_data2` | Register Read Data 2 |
| 5 | `mem_debug_data` | Memory Read Data |
| 6 | `reg_debug_addr1` | Register Read Address 1 |
| 7 | `reg_debug_addr2` | Register Read Address 2 |
| 8 | `immediate_debug` | Generated Immediate |
| 9 | `reg_write_debug` | Register Write Enable |
| 10 | `mem_read_debug` | Memory Read Enable |
| 11 | `mem_write_debug` | Memory Write Enable |
| 12 | `branch_taken_debug` | Branch Taken Status |

### VIO Interface

**Inputs (to VIO)**:
- `probe_in0`: PC Status (32-bit)
- `probe_in1`: Instruction Status (32-bit)
- `probe_in2`: Control Status Register (32-bit = 17 + 7 + 8)
  - Bits 31:15: Reserved (17'd0)
  - Bits 14:8: Current Opcode (7 bits)
  - Bit 7: Branch Taken
  - Bit 6: Mem Write
  - Bit 5: Mem Read
  - Bit 4: Reg Write
  - Bit 3: Jump Op
  - Bit 2: Branch Op
  - Bit 1: Processor Active
  - Bit 0: Error Flag

**Outputs (from VIO)**:
- `probe_out0`: Control Register (reserved for future runtime control)
- `probe_out1`: Config Register (reserved for future runtime config)

## Build and Debug Flow

### 1. Build
```bash
make implement-jtag
```

### 2. Program Board
```bash
vivado -mode batch -source - <<EOF
open_hw
connect_hw_server
open_hw_target
current_hw_device [lindex [get_hw_devices] 0]
set_property PROGRAM.FILE {build/vivado/riscv_processor_jtag_debug/riscv_processor_jtag_debug.runs/impl_1/riscv_processor_jtag_debug.bit} [current_hw_device]
program_hw_devices [current_hw_device]
EOF
```

### 3. Open Hardware Manager
```bash
vivado -mode gui -source - <<EOF
open_hw
connect_hw_server
open_hw_target
current_hw_device [lindex [get_hw_devices] 0]
open_hw_ila -name hw_ila_1
run_hw_ila
EOF
```

### 4. Configure ILA Trigger

1. Open ILA dashboard in Hardware Manager
2. Set trigger conditions:
   - **Trigger on**: `branch_taken_debug == 1`
   - **Or**: `error_flag == 1`
   - **Or**: Specific instruction pattern
3. Set capture mode: **Window** (capture before/after trigger)
4. Set capture depth: **1024** samples
5. Click **Run Trigger**

### 5. Use VIO for Runtime Control

1. Open VIO dashboard
2. Monitor `probe_in` status registers in real-time
3. Use `probe_out` for future runtime control (reserved)

## Resource Usage

| Resource | Minimal (verified) | JTAG Debug (verified) | Available |
|----------|---------|------------|-----------|
| Slice LUTs | 540 (2.60%) | 3,352 (16.12%) | 20,800 |
| FFs | 227 (0.55%) | 5,146 (12.37%) | 41,600 |
| DSPs | 0 | 0 | 90 |
| BRAM | 0 | 12 (24%, ILA capture) | 50 |
| I/O | 18 | 12 | 106 |

The core itself is 540 LUTs / 227 FFs in both builds; the JTAG build adds the ILA
(13×32-bit, depth 1024) and VIO debug cores, which consume the extra LUTs/FFs and
12 block RAMs for capture storage. JTAG post-route timing is met at 50 MHz
(WNS +3.509 ns, WHS +0.027 ns); `report_cdc` shows all crossings Safe (the dbg_hub
TCK↔clk_core crossings use the debug core's synchronizers + max-delay exceptions).
DRC and methodology each report 4 warnings, all inside the Vivado `dbg_hub`/xsdbm
debug IP (PDCN-1569, RTSTAT-10, LUTAR-1) — 0 errors/critical warnings in the user
design. See `build/reports/utilization_jtag_impl.rpt` and `timing_jtag_impl.rpt`.

## ILA Configuration

### Default Settings
- **Capture Depth**: 1024 samples
- **Trigger Mode**: Auto (manual or trigger)
- **Data Depth**: 13 probes x 32-bit
- **Clock Domain**: System clock (50 MHz)

### Customizing Capture Depth

The ILA depth is set by `create_debug_ip` in `scripts/riscv_build_common.tcl`
(`CONFIG.C_DATA_DEPTH`, default 1024), not by a wrapper parameter — the generated
IP has no overridable depth parameter. Change it there and regenerate the IP
(recreate the JTAG project) to use a different capture depth.

### Common Trigger Patterns

| Scenario | Trigger Condition |
|----------|-------------------|
| Branch taken | `probe12 == 1` |
| Error detected | `probe_in2[0] == 1` |
| Specific opcode | `probe_in2[14:8] == 7'b1101111` (JAL) |
| Specific PC | `probe0 == 32'h00000020` |
| Memory write | `probe11 == 1` |
| Register write | `probe9 == 1` |

## Troubleshooting

| Issue | Solution |
|-------|----------|
| ILA not visible | Verify the ILA/VIO IP was generated (`create_debug_ip`) and bound by name |
| No trigger | Verify probe connections, check trigger condition |
| VIO not updating | Ensure `probe_in` signals connected, check clock domain |
| Timing violation | Add false paths to debug signals in XDC |
| Bitstream too large | Reduce ILA depth, remove unused probes |
