# Timing Analysis Guide

## Overview

Timing analysis ensures the design meets setup/hold requirements at the target frequency (50 MHz for Basys3).

## Target Frequency

- **Board clock**: 100 MHz oscillator on pin W5 (`sys_clk_pin`, 10 ns period).
- **Core clock**: 50 MHz (`clk_core`, 20 ns period), generated by dividing the
  board clock by 2 with a toggle flop + BUFG in the wrapper.
- **Timing is constrained on `clk_core`** via `create_generated_clock`; the
  single-cycle datapath is timed against the 20 ns core period.

## Constraint File (XDC)

The actual `constraints/riscv_processor_minimal.xdc`:

```tcl
# Board clock: 100 MHz oscillator
create_clock -period 10.000 -name sys_clk_pin [get_ports clk]

# Generated 50 MHz core clock from the toggle-flop + BUFG divider
create_generated_clock -name clk_core -source [get_ports clk] -divide_by 2 [get_pins u_clkbuf/O]

# Reset button (async, active high) - synchronized in the wrapper
set_false_path -from [get_ports reset]

# LEDs are asynchronous status outputs - no timing requirement
set_false_path -to [get_ports {pc_debug[*]}]

# Clock uncertainty on the core clock
set_clock_uncertainty -setup 0.100 [get_clocks clk_core]
set_clock_uncertainty -hold 0.050 [get_clocks clk_core]
```

The reset and LED false-paths are intentional (async button / status LEDs); the
core logic is fully timed on `clk_core`. There is no redundant `set_max_delay`.

## Key Metrics

| Metric | Target | Actual (v1.2.0 post-route) |
|--------|--------|----------------|
| WNS (Worst Negative Slack) | >= 0 ns | +4.134 ns |
| TNS (Total Negative Slack) | 0 ns | 0.000 ns |
| WHS (Worst Hold Slack) | >= 0 ns | +0.081 ns |
| THS (Total Hold Slack) | 0 ns | 0.000 ns |
| WPWS (Worst Pulse Width Slack) | >= 0 ns | +4.500 ns |

`report_timing_summary`: **"All user specified timing constraints are met."**

## Critical Paths

### Worst core path (single-cycle datapath)
```
Register File Read -> ALU / divider iteration logic -> Data Memory
  -> Writeback Mux -> Register File Write
```

The worst post-route core path is ~15.9 ns (20 ns period − 4.134 ns WNS). RV32M
divide/remainder are computed by a **registered multi-cycle divider**
(`src/divider.sv`), so the former unrolled combinational divider is no longer in
the datapath; the worst path now includes the divider's single-iteration
compare/subtract logic and the load-use path. This comfortably meets 50 MHz with
headroom to ~63 MHz; a pipeline stage would be needed to go faster (see the
v1.3.0 roadmap). The earlier "~9.5 ns" figure was a v1.1.0 estimate.

## Timing Violations

### Common Violations

| Violation | Cause | Fix |
|-----------|-------|-----|
| Setup WNS < 0 | Critical path too long | Pipeline ALU, reduce logic depth |
| Hold violation | Short path | Add buffers, check clock skew |
| I/O setup violation | External delay too large | Adjust input/output delays |
| I/O hold violation | External delay too small | Adjust input/output delays |

### Fixing Setup Violations

1. **Pipeline ALU**: Add register stage after ALU
2. **Reduce Logic Depth**: Optimize critical path logic
3. **Increase Clock Period**: Relax frequency target
4. **Register Retiming**: Enable in synthesis

### Fixing Hold Violations

1. **Add Delay Buffers**: On short paths
2. **Clock Skew Optimization**: Balance clock tree
3. **Remove False Paths**: Check false path constraints

## Running Timing Analysis

### Via Make
```bash
make implement-minimal
cat build/reports/timing_minimal_impl.rpt
```

### Via Vivado Tcl
```tcl
open_run impl_1
report_timing_summary -delay_type max -max_paths 10
report_timing -from [get_clocks sys_clk_pin] -to [get_clocks sys_clk_pin] -max_paths 5
```

### Key Commands
```tcl
# Summary
report_timing_summary

# Top 10 worst paths
report_timing -max_paths 10

# Specific path analysis
report_timing -from [get_pins -hierarchical *alu*] -to [get_pins -hierarchical *data_memory*]

# Check clock uncertainty
report_clock_uncertainty
```

## Timing Closure Checklist

- [ ] WNS >= 0 ns
- [ ] TNS == 0 ns
- [ ] WHS >= 0 ns
- [ ] THS == 0 ns
- [ ] No unconstrained paths
- [ ] I/O constraints satisfied
- [ ] Clock uncertainty accounted
- [ ] False paths correctly defined
- [ ] DRC clean
