# ILA/VIO Integration Guide

## Overview

The JTAG debug wrapper (`riscv_processor_jtag_debug`) instantiates ILA (Integrated
Logic Analyzer) and VIO (Virtual Input/Output) cores for hardware debugging. The
IP is **generated by the build script**, not declared as black-box modules in the
RTL — see [Generated IP](#generated-ip-no-black-box-modules) below.

## ILA (Integrated Logic Analyzer)

### Probe Configuration

The ILA has 13 probes, each 32 bits wide. Narrow core signals are zero-extended
to 32 bits at the instantiation:

| Probe | Signal | Signal width | Description |
|-------|--------|--------------|-------------|
| 0 | `pc_debug` | 32 | Program Counter |
| 1 | `instruction_debug` | 32 | Current Instruction |
| 2 | `alu_result_debug` | 32 | ALU Result |
| 3 | `reg_debug_data1` | 32 | Register Read Data 1 |
| 4 | `reg_debug_data2` | 32 | Register Read Data 2 |
| 5 | `mem_debug_data` | 32 | Memory Read Data |
| 6 | `reg_debug_addr1` | 5 → 32 | Register Read Address 1 (`{27'd0, addr}`) |
| 7 | `reg_debug_addr2` | 5 → 32 | Register Read Address 2 (`{27'd0, addr}`) |
| 8 | `immediate_debug` | 32 | Generated Immediate |
| 9 | `reg_write_debug` | 1 → 32 | Register Write Enable |
| 10 | `mem_read_debug` | 1 → 32 | Memory Read Enable |
| 11 | `mem_write_debug` | 1 → 32 | Memory Write Enable |
| 12 | `branch_taken_debug` | 1 → 32 | Branch Taken Status |

### Capture Depth

The wrapper has **no `ILA_DEPTH` parameter**. The capture depth (1024 samples) is
fixed by `create_debug_ip` in `scripts/riscv_build_common.tcl`
(`CONFIG.C_DATA_DEPTH`). The generated IP stub exposes no overridable depth
parameter, so changing the depth means editing `create_debug_ip` and recreating
the JTAG project. Total trigger width: 13 probes × 32-bit = 416 bits.

### Generated IP (no black-box modules)

The `ila_riscv_processor` and `vio_riscv_processor` modules instantiated in the
wrapper are **generated IP**, created by `create_debug_ip` for the `jtag` target:

```tcl
# scripts/riscv_build_common.tcl (create_debug_ip)
create_ip -name ila -vendor xilinx.com -library ip -module_name ila_riscv_processor
# 13 probes, each 32-bit, depth 1024
create_ip -name vio -vendor xilinx.com -library ip -module_name vio_riscv_processor
# 3 probe_in / 2 probe_out, each 32-bit
generate_target {synthesis simulation} [get_ips ila_riscv_processor vio_riscv_processor]
```

The RTL intentionally does **not** define these modules. Declaring black-box
modules with the same names collides with the generated IP stubs (Synth 8-9873),
and the stub has no `C_DATA_DEPTH` parameter to override (Synth 8-7136). Vivado
binds the instantiations to the generated IP by name.

## VIO (Virtual Input/Output)

### VIO Interface

The VIO has 3 input probes and 2 output probes, each 32 bits. The wrapper connects
the inputs for monitoring and leaves the outputs unconnected (reserved):

```systemverilog
vio_riscv_processor u_vio (
    .clk        (clk_int),
    .probe_in0  (pc_debug),           // [31:0] PC
    .probe_in1  (instruction_debug),  // [31:0] Instruction
    // 17 + 7 + 8 = 32 bits
    .probe_in2  ({17'd0, instruction_debug[6:0], branch_taken_debug,
                  mem_write_debug, mem_read_debug, reg_write_debug,
                  jump_op, branch_op, processor_active, error_flag}),
    .probe_out0 (),                   // reserved
    .probe_out1 ()                    // reserved
);
```

### VIO Probe Mapping

**Inputs (probe_in)**:
- `probe_in0` (32-bit): PC value
- `probe_in1` (32-bit): Current instruction
- `probe_in2` (32-bit): Control status word, packed LSB-first:

| Bit | Name | Description |
|-----|------|-------------|
| 31:15 | Reserved | Tied to 0 |
| 14:8 | Opcode | `instruction_debug[6:0]` |
| 7 | Branch Taken | `branch_taken_debug` |
| 6 | Mem Write | `mem_write_debug` |
| 5 | Mem Read | `mem_read_debug` |
| 4 | Reg Write | `reg_write_debug` |
| 3 | Jump Op | JAL/JALR |
| 2 | Branch Op | Branch instruction |
| 1 | Processor Active | `|instruction_debug|` |
| 0 | Error Flag | core `trap` (illegal instruction / misaligned / out-of-range) |

**Outputs** (reserved for future runtime control):
- `probe_out0`: Control Register (unconnected)
- `probe_out1`: Config Register (unconnected)

## Debug Workflow

### 1. Synthesis with Debug
```bash
make implement-jtag
```
This generates the ILA/VIO IP, synthesizes, implements, and writes the bitstream
plus the `.ltx` probes file.

### 2. Program Device
```tcl
open_hw
connect_hw_server
open_hw_target
current_hw_device [lindex [get_hw_devices] 0]
set_property PROGRAM.FILE {build/vivado/riscv_processor_jtag_debug/riscv_processor_jtag_debug.runs/impl_1/riscv_processor_jtag_debug.bit} [current_hw_device]
program_hw_devices [current_hw_device]
```

### 3. Open Hardware Manager
```tcl
open_hw_ila -name hw_ila_1
run_hw_ila
```

### 4. Configure ILA Trigger

**Common Trigger Conditions**:
| Scenario | Trigger Setup |
|----------|---------------|
| Branch taken | `probe12 == 1` |
| Error detected | `probe_in2[0] == 1` |
| Specific instruction | `probe1 == 32'h0041C263` (BLT) |
| Memory write | `probe11 == 1` |
| Register write | `probe9 == 1` |
| PC reaches address | `probe0 == 32'h00000020` |

**Trigger Mode**: Window (captures before/after trigger)
**Capture Depth**: 1024 samples (set by `create_debug_ip`)

### 5. Use VIO for Runtime Monitoring

**Monitor in Real-Time**:
- `probe_in0`: Current PC value
- `probe_in1`: Current instruction
- `probe_in2[14:8]`: Current opcode
- `probe_in2[7]`: Branch taken
- `probe_in2[0]`: Error flag (core `trap`)

**Runtime Control** (future): `probe_out0` / `probe_out1` are reserved.

## Trigger Examples

### Trigger on Branch Taken
```
Trigger Condition: probe12 == 1
Trigger Mode: Window (512 before, 512 after)
```

### Trigger on Specific Instruction
```
Trigger Condition: probe1 == 32'h0041C263
Trigger Mode: Single
```

### Trigger on Error
```
Trigger Condition: probe_in2[0] == 1
Trigger Mode: Window
```

### Trigger on Memory Access
```
Trigger Condition: probe10 == 1 || probe11 == 1
Trigger Mode: Window
```

## Common Issues

| Issue | Solution |
|-------|----------|
| ILA not found | Verify the IP was generated (`create_debug_ip`) and bound by name; re-synthesize |
| No trigger | Verify probe connections, check trigger condition syntax |
| VIO not updating | Check clock domain (`clk_int`), probe_in connections |
| Timing violations | Add false paths to debug signals in the XDC |
| Synth 8-9873 / 8-7136 | A black-box ILA/VIO module or `C_DATA_DEPTH` override was re-added; remove it |
